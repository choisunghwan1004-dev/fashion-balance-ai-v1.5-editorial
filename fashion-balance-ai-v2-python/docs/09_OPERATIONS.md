# 관리자·운영·백업·장애 대응

## 운영 역할

개인 사용자는 본인 옷장·사진·스타일·이력만 관리합니다. ADMIN_EMAILS에 설정한 이메일의 인증 회원만 공용 상품 등록을 할 수 있습니다. 문서/Notion/GitHub 관리 권한과 서비스의 상품 관리자 권한은 별개입니다.

## 백업·복구

- 소스/버전: GitHub 커밋 및 배포 ZIP을 관리합니다.
- 실제 자료: MySQL fashion_balance DB와 private/uploads를 같은 시점 기준으로 함께 백업합니다.
- 비밀 설정: .env를 별도 안전한 위치에 보관하고 GitHub/Notion에 올리지 않습니다.
- MySQL Workbench의 Data Export/Import를 사용할 수 있습니다. Docker는 fashion_mysql/fashion_photos 볼륨을 유지합니다. docker compose down -v는 자료 볼륨을 삭제하므로 사용하지 않습니다.
- 복구 후 사진 파일과 private_photos 사용자 귀속, 사용자별 옷장/체형/이력을 다시 점검합니다. 소유자가 불명확한 자료를 임의로 회원에게 배정하지 않습니다.

## 장애별 확인

| 증상 | 확인 |
|---|---|
| 휴대폰 접속 불가 | PC Python 서버·같은 Wi-Fi·IPv4·방화벽·APP_BASE_URL 확인 |
| 저장 시 출처 오류 | 실제 접속 주소와 APP_BASE_URL의 프로토콜·호스트·포트 일치 |
| DB 오류 | MySQL 실행·DB_* 설정·업그레이드 SQL 적용 상태 |
| 인증 메일 미수신 | SMTP/MAIL_FROM·스팸함·앱 비밀번호·발송 제한 |
| 다른 기기에 로그인 안 됨 | 각 기기 브라우저에서 인증. 메일 앱 내부 브라우저에 로그인됐는지 확인 |
| 사진 404 | 로그인 계정·파일 소유자·실제 private/uploads 파일 일치 |
| AI 분석 불가 | API 키·한도·네트워크·동의. 수동 선택 사용 가능 |
| 추천 빈 결과 | 계절/스타일에 맞는 아우터·상의·하의·신발·예산·기준 색상 확인 |
| 아이콘 설치 안 보임 | HTTPS·Safari/Chrome 메뉴·브라우저 지원 여부. 웹으로 계속 사용 가능 |

## 정기 확인·자료 정리

인증 만료 레코드와 미참조 사진을 확인합니다. 자동 정리 스케줄은 구현하지 않았으며 사용자 확인 없이 개인 자료를 자동 삭제하지 않습니다. 사용자 삭제/탈퇴 관리 화면·비밀번호 복구·패스키는 이번 범위에 포함하지 않았습니다.
원본 사진 전송은 AI 분석 버튼과 동의를 통해서만 수행합니다. API 오류를 노출할 때 키·인증 토큰·DB 비밀번호는 기록하지 않습니다.
